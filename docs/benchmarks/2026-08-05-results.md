# 2026-08-05 retained benchmark results

These are the final retained results after three bounded optimization rounds. Round 3's LF-only batching experiment was rejected and reverted because it did not make the Node `normal-stream` result reliably positive and reduced gains in other workloads.

## Correctness

- Automated SDK gate: 5 test files, 44 tests.
- Expo/Hermes suites: 3.
- Total connections: 234.
- Measured connections: 189.
- Event count/order validation: passed.
- Hash validation: all matched.

## Node 24.18.0 / V8 parser-only fresh verification

Positive relative throughput means the candidate delivered more events per second.

| Workload          | Baseline median | Candidate median | Relative throughput | Baseline P95 | Candidate P95 |
| ----------------- | --------------: | ---------------: | ------------------: | -----------: | ------------: |
| `llm-delta`       |        0.492 ms |         0.436 ms |              1.129× |     0.542 ms |      0.471 ms |
| `tiny-chunks`     |        0.825 ms |         0.769 ms |              1.072× |     0.996 ms |      0.851 ms |
| `normal-stream`   |       10.603 ms |        10.757 ms |              0.986× |    11.289 ms |     11.067 ms |
| `large-events`    |      181.768 ms |       165.304 ms |              1.099× |   185.006 ms |    177.028 ms |
| `high-throughput` |       17.759 ms |        16.852 ms |              1.054× |    18.727 ms |     17.485 ms |

`normal-stream` was approximately 1%–2% slower by median in this retained V8 microbenchmark. Its 0.154 ms median difference is reported rather than hidden; it does not establish a universal production regression, and the candidate P95 was 0.222 ms lower in the same run.

## Expo iOS simulator / Hermes production bundle

The fair processing comparison uses `react-native-sse@1.2.1` with its initial delay explicitly set to 0 ms. “Saved vs default” separately reports the observable scheduling difference against its documented 500 ms default.

| Workload          | Open saved vs default | Open saved vs 0 ms | Total improvement vs 0 ms | Processing improvement | Throughput improvement |
| ----------------- | --------------------: | -----------------: | ------------------------: | ---------------------: | ---------------------: |
| `llm-delta`       |             514.17 ms |           12.00 ms |                   +36.08% |                 +6.92% |                 +7.46% |
| `tiny-chunks`     |             516.88 ms |           15.25 ms |                   +24.11% |                 +4.89% |                 +5.13% |
| `normal-stream`   |             518.20 ms |           15.84 ms |                   +34.58% |                +18.03% |                +22.01% |
| `large-events`    |             516.96 ms |           16.61 ms |                   +12.15% |                 +9.00% |                 +9.89% |
| `high-throughput` |             518.71 ms |           16.31 ms |                   +19.21% |                +12.38% |                +14.13% |

The approximately 500 ms observation is removal of an artificial initial scheduling delay, not evidence that the native network handshake itself became 500 ms faster.

## Retained implementation changes

1. The parser uses native string search to locate CR/LF boundaries while preserving mixed line endings and split CRLF semantics.
2. It tracks the unfinished-line scan cursor so a growing partial line is not rescanned from its beginning for every chunk.
3. The parser no longer allocates an intermediate event for every committed Last-Event-ID; the transport advances the cursor at the message-consumption boundary.

These choices were retained because the measured React Native/Hermes workloads improved without weakening the tested protocol behavior. No claim is made that Hermes or V8 must apply a particular internal optimization.
